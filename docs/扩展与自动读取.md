# 自动读取课程信息（扩展版）

目标：**登录过学校账号之后，打开/刷新本页，课程列表自己就更新了**，不用手动跑脚本、不用手动导入 JSON。

## 一、数据是怎么过来的

```
浏览器（已登录 dm.sufe.edu.cn，Cookie: S1_rman_sid）
        │
        │  chrome-extension://…/index.html  刷新
        ▼
   app.js  ──sendMessage({type:"GET_COURSES"})──▶  ext/background.js
                                                        │
                          ┌─────────────────────────────┤
                          │ ① 直连（host_permissions）   │
                          │    fetch(API, {credentials:"include"})
                          │ ② 直连拿不到时：开一个后台标签页，
                          │    让 ext/content.js 在学校页面里同源 fetch
                          ▼
                  课程列表 JSON（total 10）
                          │
                          ▼
            回到 app.js → 归一化 → 并入本地缓存（按内容哈希去重）
```

### 关键实测结论

在扩展的 service worker 里直接 `fetch` 学校接口：

```
{ "status": 200, "total": 10, "n": 10 }
```

**Cookie 带上了。** 也就是说扩展凭 `host_permissions` 发的请求，不会被
`SameSite=Lax` 挡住——这是整个方案能成立的前提。

> 作为兜底，`background.js` 仍然保留了「开后台标签页 → content script 同源 fetch」这条路。
> 如果哪天学校改了 Cookie 策略导致直连拿不到数据，它会自动退回这条路，不需要改代码。

## 二、安装

1. 打开 `edge://extensions/`（Chrome 是 `chrome://extensions/`）；
2. 右下角打开 **开发者模式**；
3. 点 **加载解压缩的扩展**；
4. 选择文件夹：`E:\dsh_Workspace\web_replay_sufe\app`
5. 装好后会自动打开一次界面；以后点地址栏右边的扩展图标即可打开。

## 三、日常使用

1. 浏览器里登录一次 `dm.sufe.edu.cn`（和平时看回放一样）；
2. 打开/刷新扩展页面 → 自动读最新一版课程列表。

没登录时页面顶部会出现一条提示：

> 还没有登录学校账号 — 点「去登录」在统一认证页登录一次…

- **「去登录」**：直接跳到学校统一认证页面（`/unifiedlogin/v1/loginmanage/login/direction`
  → 302 到 `login.sufe.edu.cn`），登录完回到这个标签页；
- **「重新检查」**：手动再读一次（这个按钮才会用「开一个后台标签页借同源请求」的兜底，
  平时不会偷偷开标签页）；
- 切回标签页（或窗口重新获得焦点）时会**自动重试一次**，只发直连请求，不打扰你。

## 四、点开课程：直接看 MP4

展开任意一门课，详情底部是「回放画面」：

```
第1周 周五 3-5节 · 09-04   第2周 …   第8周 周五 3-5节 · 10-23
┌──────────────────────────────────────────────┐
│ PPT / 屏幕                          1.21GB  打开 → │
│ 教师画面                            2.40GB  打开 → │
└──────────────────────────────────────────────┘
共 6 节课；点一下直接在新标签页里播放 MP4。
```

链路（`background.js` 的 `getMedia`）：

```
GET  /learn/v1/course/recording/video/info?courseId=…&id=…&schoolYear=…&semester=…
      → recordingVideoInfoShows[].recordInfoDetailList[].videoInfoList[]
        { videoId, videoName: "…_第1周_周一_3-5节_…_教师画面" }
POST /rman/v1/entity/download/fileinfo   body: ["videoId", …]
      → data[].downloadAddress[0]  （相对路径，拼上域名就是 MP4 直链）
```

- **节次**从 `videoName` 拆出来（`第1周` / `周五` / `3-5节` / `202609040805` 这样的时间戳），
  所以不依赖那些没文档的字段；同一节课的多路画面靠「去掉最后一节的公共前缀」归组。
- **只显示两个链接**：`屏幕画面`（就是 PPT）和 `教师画面`；`学生画面` 丢掉。
- 链是公开可读的（实测 `206 + video/mp4 + Accept-Ranges`，不带 Cookie 也能播），
  所以点开就是浏览器原生播放器，可随意拖动。
- 每门课的结果在 background 里缓存 10 分钟，同一门课反复展开不会重复请求。

## 五、去重规则

后台会算一次课程列表的哈希：

- 内容没变 → 沿用上次的 `fetchedAt`，**不会**让「第 N 次读取」虚增；
- 内容变了（回放次数、教室、课程增减）→ 记为新的一次读取，缓存里能看到 `+N` 与字段变化。

## 六、列表和缓存的关系

| | 是什么 | 什么时候变 |
|---|---|---|
| **本次列表** | 最近一次从学校读到的课程 | 每次读取成功就整体替换 |
| **全部缓存** | 本次 + 历史上读到过的所有课程 | 合并进档案，不清不会少 |
| **历史留存** | 以前有、这次列表里没有的课 | 只标 `missing`，不删除 |
| **有变化** | 回放次数或字段和上次不同 | 每次合并时比对 |

**「重置」= 清空 + 重新读一次。** 点两下（第二下变红「再点一次确认」）后：

1. 本地档案（首次/最近时间、读取次数、变化记录、历史留存）全部清空；
2. **本次列表也一起清空**，页面先变成空状态「正在重新读取最新课程…」；
3. 立刻向学校要一次最新数据，读到之后按「第 1 次读取」重新建基线。

所以重置之后计数器是真的从头开始，而不是「数据还在、只是计数归零」。
如果那一次没读到（比如登录过期），会明确提示「重置完成，但这次没读到数据」。

## 七、数据来源台账

缓存里除了课程字段，还记一本「来源账」——记的是**从哪儿读的**，不是读到了什么。

每个来源只留六样东西：接口路径、方法、状态码、响应字节数、内容指纹（sha / 短哈希）、条数，外加时间与调用次数。

| 来源 | 接口 | 现在存了什么 |
|---|---|---|
| 课程列表 | `GET /learn/v1/course/video/review/-1?…` | 状态、字节数、`hash:条数`、时间、次数 |
| 回放直链 | `GET /learn/v1/course/recording/video/info` ＋ `POST /rman/v1/entity/download/fileinfo` | 状态、两跳字节数、contentId 组合的短哈希、节次数 |
| 分章摘要 / 知识要点 | `GET /rman/v1/intelligent/select/knowledge/summary?contentId=` | 未接入，界面上显示「未取」 |
| 关键词 + 本节概要 | `GET /learn/v1/homepage/course/keywordAndAbstract?videoId=` | 未接入 |
| PPT 帧 | `GET /rman/v1/entity/file/screenshot?contentId=` | 未接入 |
| 字幕 | `GET /rman/v1/search/webvtt?contentId=` | 未接入 |
| 知识点清单 | `POST /learn/online/classroom/knowledge/point/list` | 未接入 |
| 索贝元数据 | `POST /rman/v1/search/new/relation/videos` | 未接入 |

**为什么只记来源、不记正文**（这是刻意的）：

1. 摘要、字幕、知识点都是几分钟到几百 KB 的文本，塞进 localStorage 会让缓存从几十 KB 涨到几 MB，还会挤掉 5 MB 的配额；
2. 它们是**别人的内容**，缓存里存副本没有意义——真要用的时候一个请求就能拿到，而且那边的数据比缓存里的新；
3. 存一个「内容指纹」就够判断变没变：sha 一样就是同一份，不一样下次重新取。

界面位置：展开任意课程 → 最后一块「数据来源」，一张表列出上面这些行；
`导出缓存` 导出的 JSON 里也带 `sources` 与最近 60 次调用的 `sourceLog`。

## 八、权限说明

| 权限 | 用途 |
|---|---|
| `host_permissions: https://dm.sufe.edu.cn/*` | 读课程列表接口、注入同源代理脚本 |
| `storage` | 记住上一次的数据与哈希 |

没有后端、没有账号密码、没有任何数据离开本机。

## 九、和「不用扩展」的关系

同一份 `app/index.html` 三种打开方式，行为不同：

| 打开方式 | 数据来源 |
|---|---|
| 扩展页面（`chrome-extension://…/index.html`） | 自动读学校接口（本文档） |
| `http://127.0.0.1:8730/app/`（`tools\start-server.cmd`） | 读 `app/data/courses.json` |
| 双击 `app/index.html`（`file://`） | 上次缓存，或手动「导入数据」 |
