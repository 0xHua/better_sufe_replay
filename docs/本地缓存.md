# 本地缓存：课程信息怎么存

## 一句话

每读到一次课程列表，就把它**合并**进 `localStorage` 里的一本账；重复读到同一门课不会丢旧记录，只会更新「最近看到」和变化量；这次没出现的课不会删，标成「历史」留着。

## 存在哪

| 项 | 值 |
|---|---|
| 位置 | 浏览器 `localStorage` |
| key | `sufe.replay.cache.v2` |
| 主题 | `sufe_theme`（`light` / `dark`） |
| 大小 | 10 门课约 6 KB；localStorage 上限约 5 MB，够存几千门 |
| 是否上传 | **否**。纯本地，页面没有任何网络请求 |

用 `localStorage` 而不是 IndexedDB：这份数据的量级很小（几十 KB），而且需要同步读取后立刻渲染；`file://` 下 `localStorage` 实测可用，IndexedDB 在某些浏览器对 `file://` 更挑剔。

## 数据结构

```jsonc
{
  "version": 2,
  "createdAt": "2026-10-26T02:49:00.000Z",   // 第一次记录
  "updatedAt": "2026-10-26T03:00:00.000Z",   // 最近一次写入
  "lastSnapshotAt": "2026-10-26T03:00:00.000Z", // 最近一次「读取」的时刻
  "reads": [                                  // 读取流水，最多留 30 条
    { "at": "2026-10-26T02:49:00.000Z", "count": 10 },
    { "at": "2026-10-26T03:00:00.000Z", "count": 9 }
  ],
  "courses": {                                // 以 courseId 为键
    "5e6aeafd184e4ce484d84dd230e11fdf": {
      // ……课程原始字段（与接口一致）……
      "courseName": "常微分方程",
      "playbackCount": 30,

      // ……缓存自己的元数据……
      "firstSeen": "2026-10-26T02:49:00.000Z", // 第一次见到
      "lastSeen":  "2026-10-26T03:00:00.000Z", // 最近一次见到
      "reads": 2,                              // 被记录了几次
      "viewsFirst": 30,                        // 第一次见到时的回放次数
      "viewsLast": 30,
      "viewsDelta": 0,                         // 累计变化
      "missing": false,                        // 本次列表里还在吗
      "changes": [                             // 变更历史，最多留 5 条
        { "at": "…", "fields": ["playbackCount"] }
      ]
    }
  }
}
```

## 合并规则

一次「读取」由 `snapshot.fetchedAt` 标识。**同一个 `fetchedAt` 只记账一次**——所以刷新页面、来回切视图，都不会让「已记录 N 次」虚增。

对每门课：

| 情况 | 处理 |
|---|---|
| 账上没见过 | 新建，`firstSeen = lastSeen = 本次时刻`，`reads = 1` |
| 账上有 | 覆盖字段、`lastSeen` 更新、`reads + 1`；逐字段比对，变了就记进 `changes` |
| `playbackCount` 变了 | 累加到 `viewsDelta`，界面上显示 `+3` 这种红标 |
| 本次列表里没有 | `missing = true`（**不删**），进「历史留存」视图 |

## 四个视图

| 视图 | 内容 |
|---|---|
| **本次列表** | 这次快照里的课（默认） |
| **全部缓存** | 账上所有课，含已消失的 |
| **历史留存** | 只显示 `missing = true` 的，灰字 + 虚线「历史」标 |
| **有变化** | `viewsDelta ≠ 0` 或有 `changes` 记录的 |

点开任意一行，详情底部会显示：`首次记录 · 最近记录 · 已记录 N 次`，消失的课会额外标「本次列表中已不存在」。

## 导出 / 清空

侧栏底部两个按钮：

- **导出缓存**：下载 `sufe-replay-cache-YYYYMMDD-HHmm.json`，内容是 `{ exportedAt, note, store }`，可以直接拿去备份或换机器导入；
- **清空缓存**：`confirm` 之后清空并立刻用当前快照重建（所以清完还剩本次这 10 门）。

## 限制（都是真实存在的）

1. **换浏览器 / 换 profile / 清站点数据就没了**。想长期留就定期导出。
2. `file://` 打开时，所有本地 html 共用一个 `localStorage` 空间——这不是问题，但意味着将来扩展页（`chrome-extension://`）是**另一个 origin、另一本账**，接扩展时要决定是迁移还是各存各的（建议迁移：读取时若发现旧 key 就搬过来）。
3. 现在页面的数据是**烘焙进 HTML 的快照**，所以「读取时刻」取自 `courses.json` 的文件修改时间。接上扩展之后，`fetchedAt` 会变成真实的抓取时间，这套逻辑不用改。

## 验证方法

真实数据两次读取之间没变化（11 分钟内 10 门课的回放次数一个都没动），演示不出「变化」和「历史留存」。所以另做了两份带差异的测试副本：

```
node tools/make_cache_test.js
→ probe/test/cache-a.html   （第一次读取，10 门）
→ probe/test/cache-b.html   （第二次读取：拿掉 4520、4041 回放 +5）
```

两份用的是独立的 key（`sufe.replay.cache.test`），不会污染真实缓存。
截图：`probe/shots/cache-b.png`（`+5` 红标）、`probe/shots/cache-history.png`（历史留存视图）。
